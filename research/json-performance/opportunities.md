Original provisional opportunities — continued research completed

| Opportunity                                                                                                                                                                                                                                                                                                            | Initial evidence                                                                                                   | Status                                                                           |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------|----------------------------------------------------------------------------------|
| **Avoid split-string scratch copies.** A string crossing a reader-buffer boundary is assembled in scratch storage before being copied into its owned result. Keeping it contiguous with a larger buffer, or parsing an existing input array directly, can remove that intermediate copy.                               | 64 KiB reader saved 552 ns/read (11.7%) on the 41 KB payload                                                       | Confirmed for this payload; investigate contiguous input windows and ownership   |
| **Bounded streaming writes.** Avoid allocating staging capacity for the entire object's worst-case escaped size and then copying the completed output to the sink. Keep a bounded buffer, forward long unescaped spans directly, and emit escaped data in chunks.                                                      | Handwritten large writes were 460 ns faster; generated output copies through an oversized buffer                   | Whole-implementation comparison; isolate the streaming change                    |
| **Vector configuration and fallback.** Use SIMD scanning when the JVM's vector backend is available and enabled, since the protocol defaults currently select scalar scanning. Improve the fallback by examining multiple bytes per machine word, and compare vector widths and predicates for short and long strings. | Large reads about 4× and writes about 8× faster with vectors; protocols default to scalar                          | Confirmed configuration effect; investigate scanner algorithms and vector widths |
| **Smaller hot methods.** Separate common contiguous-number and ASCII-string cases from refill, overflow, escaping and Unicode handling. Smaller helpers can fit JVM inlining limits, allowing more optimization across calls without copying every uncommon branch into the generated method.                          | JIT refuses large integer-reader and String-writer inlining; forced inlining saved about 5 ns on small ASCII reads | Diagnostic evidence; prototype fast paths and measure normally                   |

Initial numbers are provisional measurements on Ryzen 9 7950X / Corretto 26.0.1, not an absolute JVM limit. Detailed
initial results are in research.md. Further experiments, including regressions and inconclusive candidates, belong in
